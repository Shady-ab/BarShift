# BarShift - Mix & Serve

A small 2D bartending / time-management game made with Unity **6000.3.20f1**.

The player works one short bar shift. Each customer orders a fictional non-alcoholic drink, the player adds the requested ingredient amounts, follows the shake/no-shake rule, serves before patience runs out, and gets a reaction based on accuracy. Better drinks and faster service earn better tips.


## Gameplay

1. Read the order ticket.
2. Add the exact ingredient amounts.
3. Shake the drink only when the ticket asks for it.
4. Serve before the patience bar runs out.
5. The customer tastes the drink and pays according to accuracy and speed.
6. Finish six customers and try to beat the saved best shift.

## Controls

| Action | Mouse | Keyboard |
|---|---|---|
| Add ingredients | Ingredient buttons | `1` - `7` |
| Reset glass | Reset button | `R` |
| Shake | Shake button | `S` |
| Serve | Serve button | `Enter` |

## Features

- Six `DrinkRecipe` ScriptableObject assets
- `BarGameConfig` ScriptableObject for balancing
- Seven ingredients with quantity tracking
- Shake / no-shake preparation rule
- Recipe accuracy evaluation that penalizes missing and extra units
- Four customer reaction levels
- Patience timer and speed-based tip bonus
- Payment and tip system
- Six-customer shift loop
- Persistent best shift using `PlayerPrefs`
- Mouse and keyboard controls
- Runtime-built uGUI interface
- Procedurally generated sound effects (no external audio files)

## Main scripts

- `BarGameController.cs` - game state and shift flow
- `BarUI.cs` - builds and updates all UI
- `DrinkMixer.cs` - current drink contents and shake state
- `DrinkEvaluator.cs` - accuracy, reaction, payment and tip calculation
- `DrinkRecipe.cs` - ScriptableObject recipe data
- `BarGameConfig.cs` - tunable game parameters
- `IngredientType.cs` - ingredient enum, names and colors
- `CustomerData.cs` - customer presentation data
- `GameAudio.cs` - generated sound effects

## Open the project

1. Add this repository folder in Unity Hub.
2. Use Unity **6000.3.20f1**.
3. Open `Assets/Scenes/Game.unity`.
4. Press **Play**.

The project has one scene. The gameplay UI is created at runtime by `BarUI`, while recipes and game-balance values remain editable assets in `Assets/Resources/Data`.
